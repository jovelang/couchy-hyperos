# 小米电视澎湃 OS 4 适配方案

## 验证基线与限制

开发基线在 **MiTV-MTSU0 / interstellar，Android 14，OS4.0.6.0.UTSMATV** 上验证过 HOME 中转、重启、屏保协调、物理面板熄灭及方向键恢复、待机、米家开关机和 ADB 控制。型号和固件号是兼容性信息；不记录设备 serial、MAC、家庭地址或米家设备 ID。

公开整理改变了应用 ID 和配置方式，并抽出了构建模块。公开包需要在目标电视重新验收；不能把这一个固件的结果扩大为全系列或所有 OS 4 版本。带电 HDMI 实时画面、不同 HDR 编码及其他型号仍需单独测试。

## 需求与能力分层

| 需求 | 实现 | 不支持时的处理 |
| --- | --- | --- |
| HOME 到自定义桌面 | 优先标准 HOME；固件接管时使用可选 `com.ts.launcher` 前台中转 | 保留原 HOME，提供手动启动和恢复 |
| 系统设置 / 信号源 | 标准 intent + 小米入口；SourceController 读取电视输入信息 | 回退系统设置，不伪造实时预览 |
| 其他应用中遥控键映射 | 用户启用 AccessibilityService 后处理限定按键 | 只在桌面中生效，不自动开启辅助服务 |
| ADB 开关维护 | 可选中转前台服务，需所有者通过 ADB 授权 WRITE_SECURE_SETTINGS | 默认关闭；不阻止深睡 |
| 桌面屏保替换系统视觉 | 保存原系统屏保组件状态和 timeout，切换视觉入口并使用系统闲置事件 | 私有 API 失败时恢复系统入口，保留桌面内屏保 |
| 真正熄屏、按键亮屏 | 固件固定系统命令入口启动 DisplayGuard，控制物理显示面板 | 提示能力不可用，不把黑色画面当作熄屏 |
| 熄屏后待机 | DisplayGuard 调用系统电源接口，主进程负责时间和可见性 | 不宣称黑图等于关机 |
| 待机远程开机 | 独立服务器调用用户配置的 Home Assistant / 米家动作 | 没有常开主机/可用动作时提示未配置 |

## HOME 适配

部分小米固件对默认 HOME 的处理不同于标准 Android：设置默认成功后，实体 HOME 仍可能回到系统桌面。本项目采用 `fandejin/homekey-standin` 的已公开方案，在指定身份的透明前台 Activity 内转发，等待用户解锁，最多重试 30 秒，目标不可用时进入设置。

中转只有 HOME intent-filter，不出现在应用抽屉。它不是后台强行启动桌面，不能改成常驻服务无限拉起前台。`com.ts.launcher` 是兼容性约束，不是私人设备地址，也不表示厂商背书。若固件不再识别它，应记录行为并增加能力分支，不能假定永远有效。

## 屏保和电源

已知固件提供可选库 `com.xiaomi.mitv.api` / `mitvmiddlewareimpl`，代码通过反射探测 `mitv.impl.util.TvStateGc`、ScreenSaverManager 和固定系统命令入口。私有接口不是 Android 公共 API，可能受系统签名、权限或升级影响。

- 打开桌面屏保时，先持久保存 `com.xiaomi.mitv.hyper.screensaver/.MainActivity` 的原组件状态和系统屏保等待时间，再切换。关闭时恢复原值，不使用固定“恢复默认值”覆盖用户原设置。
- 系统闲置广播 `com.duokan.intent.action.show.screensaver` 由受 DEVICE_POWER 权限保护的接收器处理。直接进入系统屏保状态时，用 SaverBridge 在实际系统调用身份下启动受保护 Activity，避免把伪造的 system context 当成真正系统调用。
- 全局闲置依赖小米系统对播放和输入的判断；桌面计时只在桌面前台运行。不能保证识别所有第三方播放器、HDMI 和投屏场景；新增设备必须验证播放不被打断。
- DisplayGuard 的 Android 14 显示初始化参考 scrcpy；通过回环连接、随机 nonce 和有限命令控制恢复/待机。连接断开、心跳超时、主进程退出时尝试恢复面板，避免只显示黑图。
- 熄屏保留交互，方向键可亮屏；待机需要电源/可用的米家唤醒。ADB 是否在线不能单独决定这两个状态。

这些路径依赖固件已有的接口能力，不是通用提权工具；不分发厂商库，不接受网页传来的任意系统命令。无法通过能力探测时应降级，不能循环尝试电源控制。

## 视频和界面性能

背景采用单播放器/单渲染表面；新视频准备期间保留旧画面和切换状态，首帧和本地媒体缓存用于减少返回桌面或图片切视频时的黑闪。菜单使用稳定的半透明底色，避免周期截图生成模糊背景；应用扫描与图像提取放在后台。

优先使用匹配色彩空间的 SDR 视频。首帧、TextureView、系统截图与 HDR 色调映射可能不同，不能保证所有 HDR 素材绝对无色差。先以本地 SDR 素材排除网络、解码和色彩空间因素；性能测量使用 release 构建。

## 新型号验收清单

1. 记录型号、Android API、完整固件版本；记录标准 HOME 的解析与实体 HOME 行为。
2. 直接启动新桌面，再验证中转、冷启动、正常重启、待机唤醒和原 HOME 恢复。
3. 检查系统设置、Wi-Fi 名称、输入列表排序、信号源名称与返回行为；分别测试未连接和已通电 HDMI，描述是否真有画面。
4. 关闭/开启桌面屏保，确认原系统屏保不会双重出现，关闭后能恢复原设置；播放视频/直播、HDMI 和投屏时不应被桌面计时抢走。
5. 分别记录屏保、Awake+面板 Off、Asleep/Dozing；检查真实背光、按键恢复和退出异常时恢复。截图仍有图像不代表背光点亮。
6. 测试应用打开与 HOME 返回、固定背景循环、手动切换反馈、缓存命中、网络中断；检查持续增长的内存/缓存和解码错误。
7. 验证可选网页状态、截图、文件不覆盖、APK 安装，以及 ADB 离线后通过实际米家动作唤醒。

提交 Issue 时使用设备适配模板，先脱敏日志和截图。不要提交 ADB 地址、连接码、HA 令牌、账号、家庭 SSID、设备序列号或完整已安装应用清单。未经实测的项目写“未验证”，不要写“支持”。
